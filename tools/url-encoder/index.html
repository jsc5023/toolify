HOW IT WORKS

URL 인코더·디코더가 필요한 순간

URL에 한글·공백·특수문자가 섞이면 요청이 깨지기 쉬워요.

이럴 때 사용해 보세요

URL에 한글·공백·특수문자가 포함되면 요청이 깨지거나 서버에서 파라미터가 잘못 해석될 수 있어요. 이 도구로 인코딩·디코딩해서 링크 공유, API 테스트, 로그 해석 등에 활용하세요.

  • 한글 검색어가 포함된 링크가 깨질 때
  • API 테스트에서 쿼리스트링 값을 안전하게 만들고 싶을 때
  • 로그의 %ED%… 형태를 사람이 읽게 복원하고 싶을 때

encodeURIComponent vs encodeURI

encodeURIComponent는 쿼리 파라미터 값처럼 URL의 "부분"을 인코딩할 때 안전해요. &, =, ? 같은 예약 문자까지 전부 변환합니다.

encodeURI는 전체 URL을 인코딩할 때 사용하며, URL 구조에 필요한 예약 문자는 그대로 유지해요.

이 페이지는 브라우저에서만 동작하며, 입력한 내용은 서버로 전송되지 않습니다.

GOOD TO KNOW

궁금한 점이 있나요?

URL 인코더·디코더에 대해 자주 묻는 질문을 모았어요.

URL 인코딩은 왜 필요한가요?

URL에서 한글·공백·특수문자가 깨지지 않도록 %XX 형태로 변환하기 위해 필요합니다.

encodeURIComponent와 encodeURI의 차이는?

encodeURIComponent는 파라미터 값 같은 "부분"에 안전하고, encodeURI는 전체 URL에서 예약 문자를 유지합니다.

디코딩이 실패하면 어떻게 하나요?

% 형식이 깨져 있으면 오류가 날 수 있습니다. 입력값을 확인해 주세요.
